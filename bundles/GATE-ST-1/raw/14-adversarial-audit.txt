== A-1. Is the batch shape ACTUALLY the pinned one? The harness passes -b 2048 but
==      NOT -ub 512; it relies on the default. SPEC-R11.1 makes exact-match canaries
==      valid ONLY at '-b 2048 -ub 512 -np 1'. If the default were not 512, the
==      exact-match layer would be invalid. Checked, not assumed:
$ grep -oiE "ubatch|n_batch" server-gpu.log   -> NO MATCH: this build's server log
  does not print the batch shape at verbosity 3, so the log cannot answer it.
  Resolved from the binary's OWN default instead, which is the authority for an
  unpassed flag:

$ /opt/wrought/bin/llama-server --help | grep -A1 -- '--ubatch-size'
-ub,   --ubatch-size N                  physical maximum batch size (default: 512)
                                        (env: LLAMA_ARG_UBATCH)

  So the effective shape IS -b 2048 -ub 512 -np 1 = THE PINNED SHAPE, and the
  exact-match layer is valid. Note also that this cuts the same way for both runs:
  the 2026-08-02 baseline came from the SAME harness with the SAME unpassed flag and
  the SAME binary (sha256 verified identical, raw/03), so even had the default been
  something else, both sides of the drift diff would still share it. The finding is
  therefore: the shape is correct AND the comparison was never at risk from it. The
  latent hazard worth recording is that the harness DEPENDS ON A DEFAULT it does not
  pin -- a future llama.cpp bump that changes the -ub default would silently move the
  shape out from under the canaries. Passing -ub 512 explicitly would close that, and
  is left as a recommendation rather than an edit (the harness is Aug-2 evidence).
