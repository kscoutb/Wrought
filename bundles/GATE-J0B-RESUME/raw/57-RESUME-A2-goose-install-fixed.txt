# FINDING F-3 — guest disk headroom is a REAL constraint on this surface, not an incident.
# The noble cloud image root is 2.4G. The Goose x86_64 binary is 306,057,864 bytes UNCOMPRESSED
# (~12% of the whole guest disk) and the install path stages it three times: .tar.bz2 (85MB) +
# .tar (306MB) + extracted (306MB) = ~700MB, which filled the disk. Any future gate that puts
# this agent in a disposable guest must either grow the overlay or stream the install.

# The FIRST extract had in fact completed the ./goose member (306,057,864 bytes, archive mtime
# Aug 12 15:51); only the archive's './' directory-metadata entry failed against sticky /tmp.
# So the binary is already on disk and correct — verify it, then RENAME it into place (same
# filesystem => no second copy, which is the only way it fits).

# Enumerated deletes (rails §3) — each a scratch file THIS session created in the guest:
#   /tmp/goose.tar          306,063,360 B  intermediate tar, superseded by the extracted binary
#   /tmp/goose.tar.bz2       84,957,951 B  downloaded asset, sha256 already verified in raw/55
#   /home/probe/gooseinst/goose  75,280,384 B  TRUNCATED partial from the out-of-space extract
$ ssh probe@guest -- sha256sum /tmp/goose ; rm <3 enumerated paths> ; sudo mv /tmp/goose /usr/local/bin/goose
