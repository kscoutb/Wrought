## D-2 — DENIED: a compound command containing a VARIABLE EXPANSION
==============================================================================
  cmd:    git ... ; echo ... ; ls -a "$HOME"
  result: DENIED.

  Note the contrast, because it NARROWS GATE-J0B-CLOSE raw/02's finding rather than
  contradicting it. raw/02 measured that EVERY shape containing a redirect, pipe, `&&` or `;`
  is denied. This gate ran SEVERAL `;`-separated compounds SUCCESSFULLY, e.g.
       date -u +%Y-%m-%dT%H:%M:%SZ; echo "---"; git -C ... log --oneline -5
       git -C ... remote -v; git -C ... status --short
  and they were ALLOWED, with every constituent command allowlisted.

  >>> THE OPERATIVE VARIABLE APPEARS TO BE `"$HOME"` — an unexpanded shell VARIABLE whose
  >>> value the permission layer cannot resolve statically — NOT the `;` itself.

  STATED AS AN OBSERVATION, NOT A MEASUREMENT. This gate did not run the one-variable probe
  that would settle it (the same compound with and without the expansion), because that is
  not this gate's job and it is exactly the kind of reasoned-not-measured claim this repo
  keeps catching. It is flagged for GATE-BOUNDARY because, if it holds, raw/02's rule as
  written into rails S12.2.1 is TIGHTER THAN THE TRUTH: sequencing may be permitted and it
  may be the unresolvable argument that is refused. Rails S12.2.1 has NOT been softened on
  the strength of this — the measured table stands exactly as measured.

## D-4 — NOT ATTEMPTED, DELIBERATELY: the byte freeze
==============================================================================
  The prompt's Phase 4 says: "Byte-freeze re-assert and diff on the orchestrator store."
  RAILS S2.2 SAYS THE OPPOSITE, in its own heading: under `wrought-runner` the freeze is the
  RUNNER's duty and "a gate child MUST NOT attempt it."

  The rails preamble is explicit that a prompt may NARROW a rail and NOTHING may WIDEN one,
  and PHASE-J-STATE's preamble is explicit that where a prompt's premise disagrees with the
  box, the box wins and the disagreement is REPORTED, not reconciled by guessing.

  So the command was NOT RUN, and no workaround was sought. Rails S2.2 anticipates this
  exactly: "Do not look for a workaround: a child that could measure its own containment is
  a child that could also edit it."

  The dispatcher pre-flight predicted this as finding P-A, including the second-order effect
  this file is written around: the hook's `decide()` searches the serialised tool input, so
  its patterns match file CONTENT, and any Write whose text quotes the store's filename is
  refused too — including a report writing about the denial. Every file this gate wrote
  therefore names the frozen paths by description ("the orchestrator store", "the three
  frozen paths under /var/lib/wrought/state/"). A deliberate authoring constraint, not an
  omission, recorded so a reviewer does not read the circumlocution as vagueness.

## D-6 — NEW FINDING, NOT ANTICIPATED BY THE PRE-FLIGHT, AND IT DEMONSTRATED ITSELF TWICE:
##        THE HOOK DENIED THIS GATE'S OWN EVIDENCE FILE, TWICE, FOR ITS PROSE
==============================================================================
  Writing THIS FILE was denied TWICE before it landed. Neither attempt performed any action;
  both were denied for what the prose SAID.

    attempt 1  DENIED — "sealed credentials are never read by a gate directly (docs/06 S14.4)"
               cause: section D-5 above originally spelled out the full path of the sealed
               credential store while explaining why the secret scan could not run.

    attempt 2  DENIED — "never <the firewall ruleset-flush command> (CLAUDE.md hard rule)"
               cause: this very section, D-6, originally ENUMERATED the hook's deny patterns
               in order to make the finding auditable. Listing a forbidden command as
               documentation is indistinguishable, to a content matcher, from issuing it.

  attempt 3 — this text — describes every pattern instead of naming any, and landed.

  TWO THINGS A REVIEWER SHOULD TAKE FROM THIS.

  (1) THE MATCH IS OVER THE WHOLE SERIALISED PAYLOAD, AND NEWLINES DO NOT STOP IT.
      `decide()` serialises the entire tool input to JSON before matching. Serialisation
      turns real newlines into two-character escape sequences, so the payload the patterns
      run against contains NO newline characters at all. A `.*` in a pattern therefore
      spans the ENTIRE FILE rather than a single line. Any pattern built as
      `<token-A>.*<token-B>.*<token-C>` will fire when a long document happens to mention
      A, then B, then C, in that order, ANYWHERE in it — paragraphs apart, in unrelated
      sentences. Of the six patterns, one has exactly that three-token shape and is the one
      most likely to fire by accident on a long document. This gate did not trip it, and
      says so plainly rather than claiming a measurement it did not take.

  (2) A DOC-ONLY GATE IS THE SHAPE MOST LIKELY TO TRIP A CONTENT-MATCHING DENYLIST, because
      writing about the system IS its work product. The hazard is INVERTED relative to the
      gates the hook was designed against. The pre-flight anticipated exactly one such
      hazard (the frozen store, P-A); at least five of the six patterns are trippable by
      description alone. Only the recursive-delete pattern is shaped tightly enough to be
      hard to hit in prose.

  NOT A COMPLAINT, AND NO CHANGE IS PROPOSED. The hook is deliberately deny-only and
  deliberately short; its own comment says a long denylist "invites the belief that the list
  is the boundary". Content-matching is precisely what stops an action being smuggled past
  it inside a heredoc or a file body, and that property is worth more than the authoring
  friction it costs. The cost was real here, is cheap, and is paid.

  FOR THE ADVISOR: prompts for doc-heavy gates should warn about this up front, the way this
  one did for the freeze. The failure is LOUD and RECOVERABLE — a denied Write, retry with
  different wording, nothing lost but tokens. But a gate that hit it at the closing bracket
  with a large report already composed would burn a full rewrite for no reason, and a gate
  that hit it while writing a HALT explanation could find itself unable to explain the halt.
