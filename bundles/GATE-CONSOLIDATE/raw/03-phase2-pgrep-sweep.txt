  [L-1] bin/gate13-measure:43          *** THE SHARP ONE — IT IS A KILL ***
        stop_server() { pkill -f "$LLAMA .*--port $PORT" 2>/dev/null; sleep 3; }

        `pkill -f` with a REGEX over the whole command line, used to terminate a server.
        This is the same class as GATE-J0B-CLOSE raw/25 D-1 and raw/50 D-3, except those
        two killed their own shell and this one is aimed at a MODEL SERVER. The pattern
        `<llama-server path> .*--port <PORT>` will match ANY process whose command line
        contains that binary path and that port — which, on this box, includes the
        RESIDENT `wrought-inference.service` if it is serving on the same port with the
        same binary. The failure mode is not a self-kill; it is killing production.
        NOT VERIFIED HERE whether the ports actually collide — establishing that needs a
        run, and this gate is doc-only. Flagged as the highest-severity hit for
        GATE-BOUNDARY to measure and fix.
        Corrected form (rails §15): the sibling `start_server()` on the very next line
        ALREADY does `... & echo $!` — the pid is captured at launch and then discarded.
        Keep it and kill by pid.

  [L-2] bin/soak3-status:8
        P=$(pgrep -f "soak3-track-$t" | head -1)

        Read-only — it reports "alive pid=N", it does not signal. Lower severity, and the
        self-match risk is genuinely lower than raw/50's because this script's own command
        line is `soak3-status`, which does not contain the pattern. But it still matches
        on a command-line SUBSTRING, so an editor, a `tail`, or a `less` open on a path
        containing `soak3-track-a` is reported as a live track. That is a status tool
        reporting a false ALIVE, which is a decision input.

  [L-3] bin/soak3-track-b:174
        r = subprocess.run(["pgrep", "-a", "bwrap"], ...)

        The mildest of the three, and included for completeness rather than alarm. No
        `-f`, so this matches the process NAME, not the command line. But without `-x` the
        name match is a regex substring, so any executable whose name merely CONTAINS
        `bwrap` matches. Read-only (returns a list; `stray_bwrap()` does not kill).
        Corrected form: `pgrep -x bwrap`.
