================ THE CHANGE SET IN WORDS ================
Three regions of executable code changed. Everything else — the key-on-stdin contract, the
Authorization replacement, the per-request upstream connect, relay_exact/relay_chunked/
relay_to_eof, parse_headers, framing, handle(), main(), and apicalls.log's four-field line —
is authproxy2 byte-for-byte. The diff above is the proof of that claim, not this sentence.

  (a) BOUNDED GENERATION — new: MAX_TOKENS_BOUND, read_body(), inject_max_tokens(); and in
      serve_one, a body-buffer + head-reframe branch taken ONLY for POST .../chat/completions.
      `max_tokens` is injected when it is null OR absent, per the prompt. A client-set value
      is left alone. A non-JSON or non-object body is relayed byte-for-byte (fails OPEN).
      VALUE PROVENANCE: 24000 = pins.lock serving.reasoning_budget, whose committed n=78
      derivation calls it "the same bound already ratified for --escalation-max-tokens".
      NOT a number this gate chose. The KEY that carries it in a proxy is new -> PROPOSED-PINS-DELTA.

  (b) CANCEL ON CLIENT DISCONNECT — new class UpReader(Reader), used for the upstream side.
      It selects on upstream AND client; a client EOF sets client_gone and aborts the read,
      so serve_one returns and its EXISTING `finally: up.close()` drops the upstream socket.
      authproxy2 already had that finally — what it did not have was any way to REACH it
      while blocked in read_head(). That blocked window is precisely the F-5 wedge window.
      MSG_PEEK is used so a pipelined request is not consumed; the watch is dropped on real
      bytes so select cannot spin.

  (c) BOOKKEEPING — PIDPATH -> authproxy3.pid (so it cannot collide with authproxy2's), the
      stderr prefix, the module docstring, and one new apicalls.log STATUS token
      "CLIENT-GONE-UPSTREAM-CANCELLED" which occupies the existing status field rather than
      adding a fifth field. LOGPATH is DELIBERATELY unchanged: the same apicalls.log, so
      Phase 4 counts are a delta on a continuous record (J0B-RESUME made the same choice).
