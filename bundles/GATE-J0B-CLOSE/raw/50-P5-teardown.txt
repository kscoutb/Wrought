*** DEVIATION D-3 — THIS TEARDOWN KILLED ITS OWN SHELL, AND THE CAUSE IS A KNOWN CLASS. ***
    The step above used:   TP=$(pgrep -f "ssh -N -p 2222" | head -1) ; kill "$TP"
    `pgrep -f` matches the whole COMMAND LINE, and the command line of the shell running this
    teardown CONTAINS the literal string "ssh -N -p 2222" — because the teardown script quotes
    the pattern. So pgrep returned the teardown shell as well, and it killed itself: the
    tool call exited 144 with raw/50 truncated mid-section.

    THIS IS THE THIRD OCCURRENCE OF ONE CLASS IN TWO DAYS, and the first two are already
    written up as fixed:
      1. GATE-RUNNER-POLISH: the reaper `pgrep -f qemu-system` matched the tool-call shell of
         the session running it. Fixed there by matching /proc/<pid>/exe instead.
      2. THIS GATE, Phase 2 (raw/25 D-1): `pkill -f stub_model.py` killed the remote shell.
      3. HERE.
    The lesson the repo had already drawn — MATCH THE EXECUTABLE, NEVER THE COMMAND LINE —
    was applied to the reaper and NOT to ad-hoc session commands, which is where it keeps
    recurring. Note that the qemu check three lines above got this RIGHT (`pgrep -x`), in the
    same file, minutes earlier. Knowing the rule is not the same as having it in the fingers.

    NOTHING WAS LOST: no evidence file was truncated except raw/50 itself, which is continued
    here by APPENDING (rails §4 — never overwrite, correct by addition). State was re-measured
